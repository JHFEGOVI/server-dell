# ADR-008: HTTP Basic Auth for Admin Tools

## Status
Accepted

## Context
Some services running on the server are administration tools intended only for
personal use — Grafana being the primary example. These tools have their own
login screen, but are accessible to anyone who reaches the URL. An additional
authentication layer at the proxy level was considered.

## Decision
Enable HTTP basic authentication in Nginx for admin-facing services. The browser
prompts for credentials before the request ever reaches the service. User-facing
services intended for family use (Vaultwarden, Gitea) are excluded from this layer
to avoid unnecessary friction.

## Alternatives Considered
**Rely solely on the service's own login:** Adequate in most cases, but exposes
the service's login page to the public internet. A second layer at the proxy means
an attacker cannot even reach the application without valid credentials.

## Consequences
- Admin tools have two authentication layers — proxy and application
- The service login page is never publicly visible
- Family-facing services remain accessible without extra friction
- Basic auth credentials must be managed separately (htpasswd file)
- Credentials are sent as Base64 over HTTPS — secure in transit, not inheren
