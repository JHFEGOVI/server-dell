# ADR-002: SSL Termination at VPS Level

## Status
Accepted

## Context
The server sits on a home network behind a consumer ISP router with no port
forwarding capability. A DigitalOcean VPS acts as a WireGuard relay, receiving
public HTTPS traffic and forwarding it to the server through the tunnel.
SSL termination had to happen at one of two points: the VPS or the server itself.

## Decision
Terminate SSL at the VPS. The VPS handles the Let's Encrypt wildcard certificate
for `YOUR_DOMAIN` and proxies traffic to the server over the WireGuard tunnel.

## Alternatives Considered
**Terminate SSL at the server:** Would require passing the certificate through to
the server and decrypting at that end. The VPS→server leg is already encrypted by
WireGuard (ChaCha20-Poly1305), making a second TLS layer redundant with no security
benefit and added operational complexity.

## Consequences
- Certificate management lives on the VPS, not the server
- The VPS→server leg relies on WireGuard for encryption instead of TLS
- One fewer moving part on the server side
- If the VPS is compromised, traffic between VPS and server is still encrypted
