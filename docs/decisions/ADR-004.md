# ADR-004: Separate Docker Compose Stacks per Service

## Status
Accepted

**Date:** 2026-08-21

## Context
As the number of services running on the server grows, a decision was needed on
how to organize Docker Compose files. The two main approaches are a single
`docker-compose.yml` managing all services, or individual stacks per service.

## Decision
Each service gets its own Docker Compose stack in a dedicated directory under
`docker/`. Services are started, stopped, and updated independently.

## Alternatives Considered
**Single docker-compose.yml for all services:** Simpler to start, but grows
unwieldy quickly. A file managing five or more services becomes hundreds of lines
long. More critically, a misconfiguration or failed update in one service can
bring down the entire stack.

## Consequences
- Each service has an isolated lifecycle — restarting one does not affect others
- Easier to reason about and debug individual services
- New services are added without touching existing stacks
- Slightly more directory structure to navigate, which is a worthwhile trade-
