# ADR-005: Shared proxy-network Docker Network

## Status
Accepted

**Date:** 2026-08-21

## Context
With separate Docker Compose stacks per service, containers need a way to
communicate with the reverse proxy. By default, each stack gets its own isolated
network, meaning the Nginx proxy container has no visibility into other services.

## Decision
Create a shared external Docker network named `proxy-network`. Any service that
needs to be reachable by the reverse proxy joins this network in addition to its
own stack network.

## Alternatives Considered
**Expose ports to the host:** Each service could publish a port to the host and
Nginx could proxy to `localhost:PORT`. This works but unnecessarily exposes ports
on the host interface, increasing the attack surface. It also bypasses ufw if
Docker manages the iptables rules directly.

## Consequences
- Containers communicate by name within the Docker network — no host ports needed
- The proxy has visibility only into services that explicitly join `proxy-network`
- Reduced attack surface compared to host-exposed ports
- Requires the network to be created before any stack that uses it is started
