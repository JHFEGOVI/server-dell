# ADR-009: PasswordAuthentication Override in 50-cloud-init.conf

## Status
Accepted

**Date:** 2026-08-16

## Context
After setting `PasswordAuthentication no` in `/etc/ssh/sshd_config`, password
authentication remained active. OpenSSH on Ubuntu 24.04 processes `Include`
directives before continuing to parse the main config file. A file injected by
cloud-init at `/etc/ssh/sshd_config.d/50-cloud-init.conf` was overriding the
setting defined in the main file, regardless of where it appeared.

## Decision
Edit `/etc/ssh/sshd_config.d/50-cloud-init.conf` directly to set
`PasswordAuthentication no` at the source of the override. On this server,
cloud-init is disabled — the machine is bare metal, not a cloud instance — so
there is no risk of the file being regenerated.

## Alternatives Considered
**Set PasswordAuthentication no only in sshd_config:** Insufficient. The Include
directive causes drop-in files to take precedence over directives in the main file,
making the main file setting ineffective for any option also present in a drop-in.

**Remove 50-cloud-init.conf entirely:** Would work, but carries more risk if
cloud-init tooling is ever reinstalled or if the assumption about bare metal is
wrong. Editing the file directly is the minimal, explicit change.

## Consequences
- `PasswordAuthentication no` is enforced at the correct override point
- The behavior of OpenSSH's Include processing is explicitly documented
- Any future operator knows exactly where to look if SSH auth behavior is unexpected
- Applicable to any Ubuntu 24.04 server where cloud-init drop-ins are present
