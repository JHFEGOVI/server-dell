# ADR-007: No Host-Exposed Ports on Monitoring Stack

## Status
Accepted

## Context
During initial setup, the monitoring stack exposed ports directly to the host
(e.g., `3000:3000` for Grafana, `9090:9090` for Prometheus) to allow direct
access while the reverse proxy was not yet configured. Once the proxy was
operational, these port mappings became unnecessary.

## Decision
Remove all host-exposed ports from the monitoring stack's Docker Compose file.
Access to Grafana is routed exclusively through the Nginx reverse proxy via
`proxy-network`.

## Alternatives Considered
**Keep host-exposed ports as a fallback:** Convenient for direct access if the
proxy goes down, but Docker bypasses ufw when managing iptables rules directly.
A port published in a Compose file is reachable on the host regardless of ufw
rules, making it an uncontrolled access vector.

## Consequences
- No monitoring service is directly reachable via host port
- Access to Grafana requires the reverse proxy to be running
- ufw rules remain the effective firewall without Docker interference
- Removes a potential access vector that existed during initial setup
