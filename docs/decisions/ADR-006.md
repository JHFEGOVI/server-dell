# ADR-006: Isolated monitoring-internal Docker Network

## Status
Accepted

**Date:** 2026-08-23

## Context
The monitoring stack consists of four containers: Prometheus, Grafana, node-exporter,
and cAdvisor. All four need to communicate with each other, but only Grafana needs
to be reachable by the reverse proxy. Placing all four on `proxy-network` would give
the proxy unnecessary visibility into internal monitoring components.

## Decision
Create a dedicated internal network named `monitoring-internal` for the monitoring
stack. Prometheus, node-exporter, and cAdvisor are attached only to this network.
Grafana joins both `monitoring-internal` and `proxy-network`, acting as the single
entry point for external access.

## Alternatives Considered
**Put all monitoring containers on proxy-network:** Simpler to configure, but
violates the principle of least privilege. Prometheus, node-exporter, and cAdvisor
have no business being reachable from outside the monitoring stack.

## Consequences
- Prometheus, node-exporter, and cAdvisor are unreachable from outside the stack
- Grafana connects to Prometheus via internal Docker DNS (`http://prometheus:9090`)
- Clear network boundary between monitoring internals and the rest of the infrastructure
- Follows least privilege — each container is exposed only to what it needs
