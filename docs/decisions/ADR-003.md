# ADR-003: Manual Nginx over Nginx Proxy Manager

## Status
Accepted

**Date:** 2026-08-19

## Context
The server is a personal homelab running on a Dell Inspiron 3443 with 8GB of RAM.
The primary goal of this project is to build real systems administration skills —
not to simplify operations with GUI tooling. A reverse proxy was needed to route
incoming traffic to Docker containers across separate Compose stacks.

Two options were evaluated: writing Nginx configuration files manually or using
Nginx Proxy Manager (NPM), a GUI-based tool that manages Nginx under the hood.
Given that understanding how Nginx actually works is a core learning objective,
a tool that abstracts that away would defeat the purpose entirely.

## Decision
Use plain Nginx with manually written server blocks. Configuration files live in
`nginx/dell/conf.d/`, one file per service.

## Alternatives Considered
**Nginx Proxy Manager:** Provides a web UI for managing proxy hosts without touching
config files. Suitable for teams where not everyone edits configs directly, but it
abstracts away the underlying Nginx configuration. For a portfolio project, hiding
that layer defeats the purpose — a technical reviewer cannot tell whether the author
understands how Nginx actually works.

## Consequences
- Full visibility and control over every directive in the proxy configuration
- Changes require editing files and reloading Nginx manually — no GUI shortcuts
- Configuration is readable, version-controlled, and auditable
- Demonstrates hands-on Nginx knowledge rather than familiarity with a wrapper tool
